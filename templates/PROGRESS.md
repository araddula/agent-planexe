## Progress Rules

`PROGRESS.md` records what actually happened.

It must not become a second implementation plan.

Use:

* `PLAN.md` for intended implementation
* `PROGRESS.md` for actual implementation
* `DECISIONS.md` for important decisions and rationale
* `STATE.json` for compact machine-readable state

The executor should update this document after meaningful task progress and validation.

Do not erase previous execution history simply because a task is retried.
